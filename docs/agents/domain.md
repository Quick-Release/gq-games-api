# Domain docs

## Before exploring

Read root `GLOSSARY.md` and relevant decisions under `docs/adr/`.

If they do not exist, proceed silently. Domain modeling creates them lazily when
terminology or decisions are resolved.

## Layout

This repository uses a single context:

- `GLOSSARY.md`: shared domain terminology.
- `docs/adr/`: numbered architectural decision records.

## Vocabulary and decisions

Use glossary terms in issue titles, proposals, hypotheses, and tests. Reconsider
unfamiliar terminology or note genuine gaps for domain modeling.

Explicitly flag proposals that contradict an existing ADR, identifying the
decision and why it may need reopening.
